What this server is choosing

Implementation choices exposed by the demo

Paged KV cache

Fixed physical blocks replace grow-and-copy cache tensors. Block tables map each request’s logical tokens into stable pool locations.

Continuous batching

Every iteration mixes eligible decode rows with bounded prompt chunks, so completed or new requests join without draining the batch.

Prefix cache + COW

Exact prompt hits share block-table prefixes. A shared final block becomes private only when the next token must be written.

CUDA graph buckets

Common fixed widths replay captured work. Padded dummy rows keep shapes stable while real request counts vary.

Triton decode path

Paged attention, KV writes, RMSNorm, RoPE, and SwiGLU avoid many small eager operations during decode.

KV dtype dispatch

FP16 is the default. INT8 KV is a memory-saving option for long, saturated batches where dequantization overhead can amortize.
